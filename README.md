# Picline for Windows

Mac 上那条「截图晾衣绳」的 Windows 版。

## 这一版做了什么

| 能用 | 说明 |
| --- | --- |
| 贴顶唤出 | 指针停到任意屏幕最上面 3 像素内满 0.09 秒，绳子从屏幕顶边滑下来；**绳子上没有图时不会下来** |
| **快捷键可自定义** | 托盘右键 →「快捷键：Ctrl + Alt + T…」，按一遍新的组合即可（Esc 取消，Delete 取消设置）；被别的程序占用时会提示并保留原来的 |
| **贴顶唤出可要求按键** | 托盘右键 →「贴顶唤出」→ 不需要按键 / 按住 `Ctrl` / 按住 `Alt` / 按住 `Shift`；选了键之后不按就不放下来，选择记在 `%LOCALAPPDATA%\Picline\settings.txt`，重启保留 |
| 自动收回 | 指针离开绳子区域 0.5 秒，绳子滑回去，窗口隐藏，不留痕迹 |
| 收图 | 剪贴板一变就去看：截图工具的 DIB、浏览器／工具的 PNG、资源管理器复制图片文件，全都收 |
| 挂卡片 | 每张图挂成一张卡片，新图在右边，最多留 12 张，最旧的从左边掉下去 |
| 即时反馈 | 收到图时绳子自己下来给你看一眼，1.6 秒后收回去（指针还停在上面就不收） |
| **单击选中** | 点一下卡片，外面出现蓝色描边，表示这张被选中 |
| **Shift 连选** | 先点左边一张，按住 `Shift` 点右边一张，中间的全都选中 |
| **Ctrl 加选** | 按住 `Ctrl` 点卡片，加选或取消这一张 |
| **双击预览** | 双击卡片，全屏压暗、图片放到最大，下方写着文件名与像素尺寸；点任意位置收起 |
| **悬停出叉** | 指针停在卡片上，右上角出现深色小叉，点一下就取下这一张 |
| **卡片右键菜单** | 预览、复制图片、复制为文件、存到桌面、在资源管理器中显示、用默认看图程序打开、取下这张、取下左边全部、取下右边全部、全部取下 |
| **菜单对整组生效** | 选中三张、在其中任意一张上右键，「存到桌面」就是三张一起存，「复制为文件」就是三个文件一起放进剪贴板，「取下这张」就是三张一起取下。菜单项标题会带张数，例如「存到桌面（3 张）」。只单击了一张时仍然只对那一张。选了一组时「取下左边全部 / 右边全部」置灰 —— 一组里挑不出一张当基准 |
| **复制图片** | 写 `CF_DIB`，在微信 / QQ 输入框里 `Ctrl + V` 直接发图。剪贴板一次只放得下一张位图，所以选了一组时它只复制右键的那一张；要发多张用「复制为文件」或直接拖 |
| **复制为文件** | 写 `CF_HDROP`，粘到聊天窗口是文件消息，粘到资源管理器是拷一份 PNG；一组就是一份多文件列表 |
| **拖拽出卡片** | 按住卡片往任何地方拖：微信 / QQ 聊天窗口、桌面、任意文件夹、看图软件。拖到桌面或文件夹就是拷一份 PNG 过去（截图会给一个「Picline 2026-11-02 07-23-45.png」这样的名字；本来就有原文件的图，拖出去的是那个原文件） |
| **多选一起拖** | 选中几张之后，按住其中任意一张拖，这几张一起走：拖进聊天窗口一起发出去，拖进文件夹一起拷进去。选好之后普通点一下其中一张，松手才收敛成那一张，所以不会在拖动前把选择打散 |
| 全部取下 | 托盘右键 →「全部取下」，清空整条绳子 |
| 右键挂图 | 在资源管理器里选中一张或多张图片，右键 →「挂到 Picline」，直接挂上绳。不需要先打开程序 |
| 快捷键 | `Ctrl + Alt + T` 放下 / 收起，**可自己改**（托盘右键 →「快捷键：…」）；`Ctrl + Alt + Shift + Q` 退出 |
| 托盘菜单 | 右键托盘图标：放下 / 收起、全部取下、贴顶唤出、快捷键、资源管理器右键菜单（勾选开关）、退出 |
| 多屏与缩放 | 在哪块屏幕上贴顶，就下在哪块；按该屏的缩放比例绘制 |
| 全屏不打扰 | 检测到全屏应用或演示模式时不出来，收到图也不弹 |
| 单实例 | 重复双击不会出现两条绳子 |
| **自带的图标** | exe 里嵌了自己的图标（16–256 九种尺寸），托盘、标题栏、资源管理器里都是它，不再是 Windows 的通用程序图标 |
| **托盘图标跟随主题** | 托盘用的是单色线条版（绳 + 两张照片），任务栏设为深色就画白线、浅色就画黑线；在系统设置里切换深浅色会立刻换，不用重启 |

指针只有在**卡片上面**的时候才「接住」鼠标，其余位置一律穿透。所以整条绳子不会挡住最大化窗口右上角的最小化 / 关闭按钮。

| 还做不到 | 说明 |
| --- | --- |
| 中键 / 长按 | Mac 上的长按预览、中键标记，Windows 这边没做（预览改成了单击） |
| 多桌面 | 虚拟桌面切换时窗口不会自己跟过去 |
| 开机自启 | 要自己把 exe 的快捷方式放进启动目录 |
| webp / heic / avif | GDI+ 解不了这几种，右键菜单只对 Windows 认定的图片类型出现（png / jpg / gif / bmp / tif / ico） |

## 右键「挂到 Picline」

第一次运行就会自动写进当前用户的注册表（`HKCU\Software\Classes`，不需要管理员），菜单位置：

1. **Windows 10** —— 右键图片，菜单里直接有「挂到 Picline」
2. **Windows 11** —— 新式菜单只放系统认证过的扩展，所以要先点「显示更多选项」（或直接按 `Shift + F10`），在传统菜单里
3. 多选也支持：框选几张再右键，会一次全挂上
4. 程序没在跑也没关系：点它会先把程序拉起来，再挂图

不想留这个菜单项，托盘右键 →「资源管理器右键「挂到 Picline」」取消勾选即可，注册表键会一起删掉。

Windows 11 的「新式菜单」之所以进不去，是因为它只接受 MSIX 打包或有签名的 COM 扩展；我们这种免安装的单个 exe 只能出现在传统菜单里。这也是免安装的代价之一。

## 怎么试

1. 把 `Picline-0.1.12-win-x64.exe` 拷到 Windows 机器上（ARM 机器用 `-win-arm64.exe`）。
2. 双击。首次运行会因为未签名被 SmartScreen 拦一下：点「更多信息 → 仍要运行」。
3. 用微信截图、`Win + Shift + S`、或随手复制一张图片。
4. 绳子应该自己下来，图片以卡片形式挂上去，1.6 秒后收回。
5. 把鼠标推到屏幕最上面，稍微停一下，绳子带着那几张卡回来。
5.1 把指针移到某张卡上：右上角出现小叉；点小叉即取下这一张。
5.2 点卡片本体：外面出现蓝色描边（选中）；双击才全屏放大预览，点任意位置收起。
5.2.2 选中三张后在任意一张上右键 →「存到桌面（3 张）」，桌面上会多三个 png。
5.2.1 先点最左一张，按住 `Shift` 点另一张，中间的全都选中；按住其中一张拖出去，是一起走。
5.3 在卡片上右键：菜单里试「复制图片」，然后到微信输入框里 `Ctrl + V`。
5.4 右键 →「存到桌面」，桌面上会多一张 `Picline 2026-11-02 07-23-45.png`。
5.5 按住一张卡往微信输入框里拖，松手就是一张图；往桌面或某个文件夹里拖，松手就多一个 png。拖的时候绳子会让开鼠标，不会挡住落点。
6. 在任意文件夹里右键一张图片 →「挂到 Picline」（Win11 要先点「显示更多选项」）。
7. 右键托盘图标 →「全部取下」清空。

## 收不到图时

程序会把每次剪贴板变化记到 `%LOCALAPPDATA%\Picline\picline.log`，里面写着剪贴板当时到底有哪些格式，例如：

```
clipboard holds: CF_UNICODETEXT, CF_DIB, CF_DIBV5
took 1 picture(s) 1920x1080
```

如果某次截图没挂上，把那几行发出来就能看出是格式没认出来、还是读取时剪贴板被别人占着。

## 在 Mac 上编译

不需要 Windows，也不需要虚拟机。工具链：Rust + llvm-mingw 交叉链接。

```bash
# 1. Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
export PATH="$HOME/.cargo/bin:$PATH"
rustup target add x86_64-pc-windows-gnullvm aarch64-pc-windows-gnullvm

# 2. llvm-mingw（提供 linker 和 Windows 导入库）
#    https://github.com/mstorsjo/llvm-mingw/releases 下的 *-ucrt-macos-universal.tar.xz
mkdir -p ~/toolchains && tar -xf llvm-mingw-*-ucrt-macos-universal.tar.xz -C ~/toolchains

# 3. 出包
scripts/build-win.sh both      # 产物在 dist/
```

`.cargo/config.toml` 里写的是这台机器上的绝对路径，换机器要改；包装脚本 `~/toolchains/bin/*-gnullvm-cc` 只是把 clang 的 target 钉死。

几个踩过的坑，记在这里省得再踩：

- Rust **没有** `aarch64-pc-windows-gnu`，ARM64 只有 `gnullvm` 和 `msvc`；x64 两个都有。
- `windows-gnu` 目标要 `-lgcc` / `-lgcc_eh`，llvm-mingw（LLVM 运行时）里没有，所以走 `gnullvm`。
- `gnullvm` 默认动态链 `libunwind.dll`，那个 DLL 用户机器上没有。解法是把 llvm-mingw 的静态 `libunwind.a` 单独放一个目录，用 `-L` 让它被优先找到（`.cargo/config.toml` 里的 `static-unwind` 路径）。
- 产物只有系统 DLL 依赖（`gdiplus` / `user32` / `gdi32` / `shell32` / `shlwapi` / UCRT），Win10、Win11 都自带。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `res/picline.ico`、`res/picline.rc` | 应用图标与资源脚本；16/20/24 是照着小尺寸重画的，32 以上用主图缩放。另有两份单色托盘图标（浅色线 / 深色线） |
| `build.rs` | 用 windres 把图标编成 COFF 对象再交给链接器（GNU 目标没有别的办法）；找不到 windres 时只警告，不影响编译 |
| `src/hotkey.rs` | 快捷键：解析、注册、以及按一遍就记下的录制窗口 |
| `src/settings.rs` | 用户选择的持久化：`%LOCALAPPDATA%\Picline\settings.txt` 里的 key=value |
| `src/main.rs` | 窗口、消息循环、贴顶状态机、动画、卡片排版、悬停与命中测试、卡片右键菜单、托盘、热键、命令行 `--hang`、单实例转发 |
| `src/clipboard.rs` | 剪贴板监听与四种格式解析（HDROP / DIBV5 / DIB / BITMAP / PNG），写回剪贴板（DIB / HDROP），存 PNG 到桌面，收图去重，日志 |
| `src/preview.rs` | 全屏预览窗：压暗桌面、等比放大、文件名与尺寸、点一下收起 |
| `src/drag.rs` | 手写的 OLE 拖放：`IDataObject`（只给 `CF_HDROP`）、`IEnumFORMATETC`、`IDropSource` 三张虚表，`DoDragDrop` |
| `src/shellmenu.rs` | 注册表里的「挂到 Picline」动词：装、卸、查 |
| `src/canvas.rs` | 32 位 DIB + `UpdateLayeredWindow`，逐像素透明 |
| `src/gdiplus.rs` | 手写 GDI+ 绑定：曲线、圆角、文字、图片解码、缩放、PNG 编码 |

剪贴板和右键菜单最后都走 `clipboard::shot_from_path` / `unpack_dib`，出口是同一个 `Shot`，所以两种来路的图在绳子上长得一模一样。

GDI+ 的绑定是手写的（没用 `windows` crate 的 GdiPlus 模块），这样升级 crate 时不会因为绑定增删而编译失败。

## 已验证到什么程度

这台机器是 Mac，**exe 只能编译、不能运行**。已经做过的是：

- 两个架构都能交叉编译、链接，导入表里只有系统 DLL。
- `unpack_dib` 那段字节运算单独抽出来在本机跑过 7 组人造数据：32 位自下而上、alpha 全 0 视为不透明、24 位行填充、高度为负自上而下、`BI_BITFIELDS` 掩码跳过、短数据被拒、16 位被拒。
- `WM_COPYDATA` 那条路径的打包／拆包单独抽出来跑过：空列表、单个 ASCII 路径、三个带空格与中文的路径、以及尾部少一个 NUL 的残包，都能原样往返。
- 二进制里核对过写进注册表的字符串（键路径、菜单文字、`MultiSelectModel`、`--hang %* "%1"`）和导入表（多了 `advapi32.dll`，没有额外的运行时 DLL）。

0.1.4 这些交互**没有在真机上跑过**（本机是 Mac，只做交叉编译）。能验证的都验证了：虚表顺序对着 `windows` crate 的定义逐项核对，`FORMATETC` / `STGMEDIUM` / `GUID` 的尺寸用编译期断言钉住（32 / 24 / 16 字节），`DROPFILES` 的字段偏移按 SDK 布局写（路径列表从第 20 字节起，`fWide = 1`）。真正的 OLE 往返只能靠那台 Windows。

`picline.log` 里会留下痕迹：按下拖拽（`drag of shot N: <路径>`）、拖拽结束（`drag finished: hr … effect …`）、右键、点叉、开预览、菜单选项各写一行。出问题时把最后几十行发回来就能定位。

没做的是：真机运行。所以第一次跑还是要靠那台 Windows。
